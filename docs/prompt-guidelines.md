# 提示词编写规范

修改 SKILL.md 或 `references/` 下任何提示词文件之前，先读完本文。

## 内容规范

- SKILL.md frontmatter：`name` 固定为 `waibao`；`description` 必须同时写清触发场景与排除场景（如「小型代码修改或单点提问不要使用」）。
- 跨工具适配以「能力」而非工具名描述依赖；具体框架的工具映射只落在 SKILL.md「跨工具适配」表，不写进角色提示词。E2E 工具（Playwright CLI、WDIO MCP、Appium）的命令与 API 细节**不固化在任何提示词中**：场景路由表以 `references/e2e/index.md` 为唯一事实源，角色提示词不复制路由表，只保留执行原则与本角色特有禁令，工具说明文件只保留场景纪律与操作环节，用法细节以各工具官方文档（检索入口在各工具说明文件内）与运行时自描述为准。
- 规则、评分、映射关系用表格呈现；产物文档（PRD、QA 报告、state.md 等）用 markdown 代码块给出完整模板。
- 角色提示词保持既有骨架：角色定位（含行为准则）→ 调度方式 → 核心禁令 → 流程 → 格式模板 → 被打回时。新增内容归入既有章节，不另起平行体系。

## AI 优先书写风格

提示词的读者是模型，不是人。所有提示词按以下风格编写与修订：

1. **指令式书写**：规则写成「条件 → 动作」；禁叙述句、口语语气词与比喻。
2. **人设仅保留行为约束**：角色定位压缩为职责 + 行为准则；不写从业年限、性格比喻等无行为约束力的装饰。
3. **规则可判定**：凡约束性的「必须 / 不得」，附可判定的阈值或判据，禁「合理」「明显」「适当」等模糊词；禁令一律用硬规则语气，不用建议性语气。
4. **单一事实源**：同一规则在一个文件内只定义一次，他处指涉不复制；跨文件重复仅限子代理隔离所必需（同一规则需分别注入不同子代理）。
5. **一段一事**：一个列表项 / 段落只承载一件事，多项信息拆子列表或表格。
