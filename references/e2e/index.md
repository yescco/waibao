# E2E 工具路由与上报

> Pm 与 Qa 共用的 E2E 工具事实源。Pm 调度 Qa 时，除注入 `references/qa-prompt.md` 外，会一并注入本文件与按被测形态选定的工具说明文件。

## 场景路由表

E2E 工具按**被测目标形态**选择，禁止不区分场景一律使用同一工具。判定依据是「访问方式」而非页面风格：

| 场景 | 工具 | 说明文件 |
| ---- | ---- | -------- |
| PC Web 页面（URL 可访问的页面，含移动端风格的 H5 页面） | `playwright-cli` | `e2e/playwright-cli.md` |
| Electron 桌面应用 | `playwright-cli`（CDP 附加） | `e2e/playwright-cli.md` |
| 移动端（iOS/Android 真机或模拟器，经 Appium） | WDIO MCP（`@wdio/mcp`） | `e2e/wdio-mcp.md` |

**核心原则：被测应用是什么平台，E2E 就必须在该平台的真实运行上下文中执行，禁止跨上下文取巧**——PC Web 在真实浏览器中访问目标 URL；Electron 在真实运行的应用进程中测试（Pm 以调试端口启动后 CDP 附加），浏览器里打开的渲染页面 / dev URL 不是 Electron 上下文；移动端在真机/模拟器中测试，桌面浏览器的视口模拟不是移动端上下文。

## 共通执行规范

适用于所有工具：

- **会话先行，切忌未建会话直接操作页面**：所有页面操作都依赖已存在的会话。正确顺序：建立会话 → 打开目标页面 → 操作 → 关闭会话，一次 E2E 恰好一对开闭。
- **浏览器必须以有头模式运行**：无头模式的渲染问题（视口/布局差异、懒加载与动画不触发等）会使页面表现与真实用户所见不符、测试结果与截图证据不可信。启动参数见各工具说明文件。
- **交互前先获取真实元素标识再操作**，不要凭空猜测元素。获取方式见各工具说明文件。
- **截图证据必须落盘**为 `<迭代目录绝对路径>/evidence-N.png`，至少 1 张。落盘命令见各工具说明文件；若当前环境无法落盘，在报告中注明并以对话内截图为证。
- **测试结束务必关闭会话**，避免残留进程。Electron 场景 Qa 只负责关闭/断开会话，被测应用进程由 Pm 负责关闭。

## Pm 上报处理流程

Qa 上报工具不可用时，或 Pm 调度 Qa 前确认工具可用性时，按以下流程处理：

1. **PC Web / Electron 场景（playwright-cli 不可用）**：询问用户是否安装 playwright-cli——全局安装 `npm install -g @playwright/cli@latest`，或直接以 `npx playwright cli` 免安装使用。安装属用户级操作，项目目录零侵入，即时生效、无需重启会话。
2. **移动端场景（WDIO MCP 未配置）**：告知用户当前环境未配置移动端 E2E 工具，询问是否现在配置 `@wdio/mcp`（WebDriverIO 官方 MCP server，支持 iOS/Android 真机与模拟器）。用户同意则按当前 agent 工具自身的 MCP 配置方式引导注册，Pm 不预设、不写死任何工具的具体配置细节；建议注册在用户级/工具级配置中，保持项目目录零侵入。配置生效可能需要重启会话——工作流状态已持久化在 `state.md`，重启后重新触发本 skill 即可按「中断恢复」续接，然后重新调度 Qa。
3. **Electron 场景（被测应用未以调试端口运行）**：由 Pm 以后台方式启动被测应用并暴露调试端口（如 `npx electron . --remote-debugging-port=9222`，以后台任务运行避免阻塞），**确认端口可访问（如 `curl http://localhost:9222/json/version` 有响应）后再告知 Qa**，确保 Qa 能 attach 到真实应用进程执行 E2E、不降级取巧；Qa 的 E2E 结束后由 Pm 负责关闭该进程。Pm 不受 Qa 的 Bash 安全原则约束，但必须后台运行、事后清理，不留残留进程。
4. **用户拒绝安装/配置**：通知 Qa 按「E2E 降级模式」继续验收——功能性、视觉设计两维度不评分并注明原因，产品完整性与代码质量照常评分，迭代不因此判不通过，验收责任转移至用户 UAT。降级不消耗退化计数。
