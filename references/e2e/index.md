# E2E 工具路由与上报

> Pm 与 Qa 共用的 E2E 工具事实源。Pm 调度 Qa 时，除注入 `references/qa-prompt.md` 外，会一并注入本文件与按被测形态选定的工具说明文件。

## 场景路由表

E2E 工具按**被测目标形态**选择，禁止不区分场景一律使用同一工具。判定依据是「访问方式」而非页面风格：

| 场景 | 工具 | 说明文件 |
| ---- | ---- | -------- |
| PC Web 页面（URL 可访问的页面，含移动端风格的 H5 页面） | WDIO MCP（`@wdio/mcp`） | `e2e/wdio-mcp.md` |
| Electron 桌面应用 | WDIO MCP（Electron 会话） | `e2e/wdio-mcp.md` |
| 移动端（iOS/Android 真机或模拟器，经 Appium） | WDIO MCP（`@wdio/mcp`） | `e2e/wdio-mcp.md` |

被测形态不在路由表内（如 Tauri 桌面应用）时，Qa 向 Pm 上报，按「Pm 上报处理流程」交用户决策，**不得自行默认按任一场景处理**。

**核心原则：被测应用是什么平台，E2E 就必须在该平台的真实运行上下文中执行，禁止跨上下文取巧**——PC Web 在真实浏览器中访问目标 URL；Electron 由 E2E 工具拉起真实应用进程测试，浏览器里打开的渲染页面 / dev URL 不是 Electron 上下文；移动端在真机/模拟器中测试，桌面浏览器的视口模拟不是移动端上下文。

## 共通执行规范

适用于所有场景：

- **WDIO 用法以官方文档为唯一事实源**：索引 `https://webdriver.io/llms.txt`（每条目为「标题 + 链接 + 一句话摘要」），单页在文档页 URL 后加 `.md` 后缀，全量文档 `llms-full.txt`；环境提供文档检索类工具（如 `query_docs`）时优先使用。**用法不确定的 API、配置、工具参数，先查文档再使用，禁止凭记忆或旧版经验调用。**命令与 API 细节不固化在本目录任何提示词中，以官方文档与运行时工具自描述为准。
- **一次 E2E 一次完整会话生命周期，切忌中途断开重连或遗留进程**：启动会话 → 打开目标 → 操作 → 截图 → 关闭会话，恰好一对开闭。
- **浏览器必须以有头模式运行**：无头模式的渲染问题（视口/布局差异、懒加载与动画不触发等）会使页面表现与真实用户所见不符、测试结果与截图证据不可信。若工具默认无头，启动会话时显式关闭。
- **交互前先获取真实元素标识再操作**，不要凭空猜测元素。获取方式见工具说明文件。
- **截图证据必须落盘**为 `<迭代目录绝对路径>/evidence-N.png`，至少 1 张。落盘方式见工具说明文件；若当前环境无法落盘，在报告中注明并以对话内截图为证。
- **测试结束不留残留进程**：E2E 结束关闭会话。

## Pm 上报处理流程

Qa 上报工具不可用或被测形态超出路由表时，或 Pm 调度 Qa 前确认工具可用性时，按以下流程处理：

1. **WDIO MCP 未配置（PC Web / Electron / 移动端场景通用）**：告知用户当前环境未配置移动端/浏览器 E2E 工具，询问是否现在配置 `@wdio/mcp`（WebDriverIO 官方 MCP server，支持桌面浏览器、Electron 应用与 iOS/Android 真机/模拟器）。用户同意则按当前 agent 工具自身的 MCP 配置方式引导注册，Pm 不预设、不写死任何工具的具体配置细节；建议注册在用户级/工具级配置中，保持项目目录零侵入。配置生效可能需要重启会话——工作流状态已持久化在 `state.md`，重启后重新触发本 skill 即可按「中断恢复」续接，然后重新调度 Qa。
2. **Electron 场景（应用入口未提供）**：由 Pm 从项目配置（如 `package.json`、构建产物入口）确认 Electron 项目根目录与应用入口信息，提供给 Qa 供其以 E2E 工具拉起真实应用。
3. **被测形态超出路由表（如 Tauri）**：告知用户当前工作流暂不支持该形态的 E2E 工具，询问是否按降级模式验收或由用户另行决策。
4. **用户拒绝安装/配置**：通知 Qa 按「E2E 降级模式」继续验收——功能性、视觉设计两维度不评分并注明原因，产品完整性与代码质量照常评分，迭代不因此判不通过，验收责任转移至用户 UAT。降级不消耗退化计数。
